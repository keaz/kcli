## What Was Implemented

### 1. Core ACL Functions
- **`list_acls()`**: List ACLs with optional filtering by resource type, resource name, and principal
- **`create_acl()`**: Create new ACL entries with full parameter validation
- **`delete_acl()`**: Delete ACL entries matching specified criteria

### 2. Data Structures
- **`AclBinding`**: Serializable struct representing ACL configuration
  - resource_type: Type of resource (topic, group, cluster, etc.)
  - resource_name: Name of the resource
  - resource_pattern: Pattern type (literal, prefixed, match)
  - principal: User or group principal
  - operation: ACL operation (read, write, create, etc.)
  - permission: Allow or deny
  - host: Host restriction

### 3. Validation Functions
Comprehensive validation for all ACL parameters:
- `validate_resource_type()`: Validates resource type against allowed values
- `validate_operation()`: Validates operation type
- `validate_permission()`: Validates permission type (allow/deny)
- `validate_pattern_type()`: Validates pattern matching type
- Empty parameter checks for resource name and principal

### 4. Error Handling
- New error variant: `KafkaError::InvalidAclParameter` for validation errors
- Clear, descriptive error messages
- Proper error propagation from subprocess execution
- Graceful handling when kafka-acls.sh is not available

### 5. Script Discovery
- `find_kafka_acls_script()`: Automatically locates kafka-acls.sh
  - Searches PATH first
  - Falls back to KAFKA_HOME environment variable
  - Returns clear error if not found

## Usage Examples

### List all ACLs
```bash
kfcli acl list
```

### List ACLs for a specific topic
```bash
kfcli acl list --resource-type topic --name orders
```

### Create an ACL
```bash
kfcli acl create \
  --resource-type topic \
  --resource-name orders \
  --principal User:alice \
  --operation read \
  --permission allow
```

### Delete an ACL
```bash
kfcli acl delete \
  --resource-type topic \
  --resource-name orders \
  --principal User:alice \
  --operation read \
  --permission allow
```

## Technical Implementation Details

### Subprocess Execution
- Uses `std::process::Command` to execute kafka-acls.sh
- Captures stdout and stderr
- Returns appropriate success/error based on exit status
- Automatic confirmation (--force) for delete operations

### Parameter Validation
All parameters validated before subprocess execution:
- **Resource Types**: topic, group, cluster, transactionalid, delegationtoken
- **Operations**: read, write, create, delete, alter, describe, clusteraction, describeconfigs, alterconfigs, idempotentwrite, all
- **Permissions**: allow, deny
- **Pattern Types**: literal, prefixed, match

### Error Handling Strategy
1. Parameter validation errors caught early
2. Script discovery errors provide clear installation instructions
3. Kafka errors from kafka-acls.sh propagated with context
4. All errors typed using KafkaError enum
