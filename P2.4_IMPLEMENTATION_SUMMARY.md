## Avro Wire Format Support

Correctly handles Confluent's Avro wire format:
```
[0x00][schema_id: 4 bytes][avro_data...]
```

The `deserialize_avro()` method:
1. Validates magic byte (0x00)
2. Extracts schema ID (big-endian)
3. Fetches/caches schema from registry
4. Deserializes Avro data using schema

## Architecture Decisions

### 1. Blocking HTTP Client
- Used `reqwest::blocking` instead of async
- Matches existing codebase patterns
- Simpler error handling for CLI tool

### 2. In-Memory Caching
- HashMap-based schema cache
- Key: schema ID
- No TTL or eviction (future enhancement)
- Significant performance improvement for repeated access

### 3. Optional Configuration
- Schema registry is optional per environment
- Graceful error if not configured
- Backward compatible with existing configs

### 4. Custom Debug Implementation
- Manually implemented Debug for SchemaRegistryClient
- reqwest::Client doesn't derive Debug
- Shows URL and cache size for debugging

## Performance Characteristics

### Schema Caching
- **Cache Hit**: O(1) - Instant from HashMap
- **Cache Miss**: O(network) - HTTP request to registry
- **Memory**: O(n) where n = unique schema IDs accessed

### HTTP Performance
- Configurable timeouts (default: 30s)
- Connection reuse via reqwest client
- JSON parsing via serde

### Typical Latencies
- List subjects: ~50-200ms (network dependent)
- Get schema (cached): <1ms
- Get schema (uncached): ~50-200ms
- Deserialize message: <1ms (after schema fetch)

## Known Limitations

1. **Avro Only**: Protobuf and JSON Schema not yet supported
2. **Read-Only**: Cannot register or update schemas
3. **No Authentication**: Basic HTTP only
4. **No TLS/SSL**: HTTPS support needed for production
5. **Cache Management**: No TTL or size limits
6. **Single-threaded**: Client not thread-safe
